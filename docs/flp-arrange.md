# .flp アレンジ形式 (検討メモ / ブランチ flp-arrange)

既存の `.flp` 出力 (`--flp`、`buildFlp`) はそのまま残し、新しいモードとして **アレンジ形式** (`--flp-arrange`、`buildFlpArrange`) を追加する。

## 目的

- 1 パターンに全部詰め込むのをやめ、**1 トラック = 1 音色の塊** にしてプレイリスト上に並べる
- ADPCM は sforzando + SF2 をやめ、**WAV を FL 標準の Sampler で鳴らす**
- MXDRV との互換性はできるだけ保つ。どうしても無理な部分は、**プレイリストの自由度を優先する別モード**として分ける

## モード構成

| モード | CLI | 状態 |
|---|---|---|
| 従来 (1 パターン) | `--flp template.flp` | 変更なし (8 曲の出力がバイト一致することを確認済み) |
| アレンジ・互換 | `--flp-arrange template.flp [--sample-root DIR]` | 試作済み |
| アレンジ・自由度優先 | (未定) | 設計のみ。OPM68 0.7 が必要 |

## アレンジ・互換モードの構造

### FM

- チャンネルラック: 従来どおり **MDX 1ch = OPM68 1 台 (Mono)**。FM A〜H の 8 台
- プレイリストトラック: **(MDX チャンネル, 音色) ごとに 1 本** (例: `FM E @3`、`FM E @10`)。OPM68 モードではノートのベロシティ = バンクスロット + 1 なので、音色はノートごとに決まる
- クリップ: 各トラックのノートを**フレーズ**に分ける。区切りは「1 小節 (192 クロック) 以上の休符」と「ループ開始点」。クリップの頭は小節線にそろえる
- パターン: **内容が完全に同じクリップは 1 つのパターンを共有**する (繰り返しフレーズがプレイリスト上で同じパターンとして見える)
- 制御ノート (キー 0〜14 のパケット) とパン: **そのチャンネルで次に鳴るノートのクリップ**に入れる (最後のノートより後ろは最後のクリップ)。同じクロックのパケットとノートは必ず同じパターンに入る
- FM の音色ごとにトラックを分けても、全パターンが同じ OPM68 の同じ位置にノートを送るので、**鳴り方は従来の .flp と同一**

### ADPCM (Sampler)

- 使われた PDX サンプル (バンク, 番号, 周波数) ごとに WAV (16bit モノラル、元のレート) を 1 つ書き出し、Sampler チャンネル 1 本とプレイリストトラック 1 本を割り当てる。周波数ごとに WAV を分けるので、ノートは常に C5 (60)
- ノートの長さ = 同じ ADPCM チャンネルの次のノートまで (MXDRV は 1ch で 1 サンプル)。ただしサンプルの長さを上限にする
- ベロシティ = CC7 × CC11 (音量とフェード)、ノートパン = CC10
- チャンネルは、テンプレートに Sampler チャンネルがあればそれを複製する。無ければ FL Studio 26.1.6 が保存した Sampler チャンネル 1 本分のイベント列 (変換器に内蔵) を複製し、名前 (203)・サンプルパス (196)・ミキサーの送り先 (104、テンプレートの ADPCM と同じ) を書き換える。最初の 1 本は sforzando の ADPCM チャンネルの位置に入れる
- プラグインチャンネル (sforzando) のタイプを 0 にしただけのものは、FL が 212 のヘッダからラッパーとして扱い、全サンプルを「無効なサンプル」にした (2026-10-04 確認)。本物の Sampler は 201 が空文字、212 のプラグイン種別が 0xffffffff
- カットグループ (132) は 0 (なし)。切るタイミングはノートの長さで決める
- サンプルパス: CLI は既定で絶対パス。`--sample-root D:\...` で書き込むパスの頭を指定、`--sample-root .` で `<曲名>_samples\xx.wav` の相対パス

### 互換性の確認方法

`.flp` を読み、プレイリストの全アイテム × パターンの中身を絶対位置に展開して、従来の `.flp` の Pattern 1 と比較した (FM のノート・制御ノート・パンイベントの位置・長さ・キー・ベロシティ)。テスト 8 曲すべてで一致。

| 曲 | トラック | クリップ | パターン | Sampler |
|---|---|---|---|---|
| 01 GOFERHE | 36 | 84 | 78 | 23 |
| 02 qua_st3 | 17 | 118 | 109 | 0 |
| 03 stc11 | 27 | 110 | 51 | 0 |
| 04 XakM39 | 26 | 125 | 61 | 7 |
| 05 TC_GB | 22 | 99 | 69 | 10 |
| 06 ult0 | 23 | 87 | 87 | 3 |
| 07 SORMD35 | 23 | 69 | 56 | 0 |
| 08 dq4_10s | 14 | 58 | 58 | 0 |

ADPCM の WAV は X68000 の出力フィルタ (x68sound のモデル、62.5 kHz) をかけて書き出す (README「ADPCM の音質」)。SF2 版も同じフィルタをかけ、PCM8 でない曲は exclusiveClass でモノフォニックにした。

## 互換モードの制約 (クリップを自由に動かせない理由)

互換モードは「元の位置に置いたときに同一」であることを保証するだけで、クリップを動かしたりコピーしたりすると音が変わることがある。

1. 制御パケットは**差分** (変化したときだけ送る)。クリップを別の場所に置くと、音量・デチューン・LFO 設定・クロック長などが移動先の直前の状態のままになる
2. MXDRV のソフト LFO は、LFO ディレイ 0 ならキーオンでリセットされず走り続ける。OPM68 の LFO 設定アイテムはリセットを伴うので、状態の再送で代用できない
3. 音量アイテムは y コマンドによる TL の上書きを消す (`clearTlOverrides`)。これも再送すると元の位置で鳴り方が変わる
4. ハード LFO はチップ共通なので、位相は曲頭でそろえた全体の流れに依存する

FM で音色の違うクリップを同じ時刻に重ねると、同じ OPM68 (Mono) で鳴るので後のノートが前のノートを切る。これは元の MDX と同じ。

## アレンジ・自由度優先モード (案)

上の 1〜3 を解決するために、**各クリップの頭に状態のスナップショット**を置く。

- OPM68 0.7 で制御パケットに「RESTORE」アイテムを追加する (例: type 4 param 4)。これ以降の同じパケットのアイテムは、**値が現在と同じなら何もしない** (LFO をリセットしない、TL の上書きを消さない)
- スナップショット: クロック長・音量・フェード・デチューン・ピッチ/振幅 LFO の設定と ON/OFF・LFO ディレイ・ハード LFO レジスタ ($18 / $19 PMD・AMD / $1B / $38+ch)。パン (コントローライベント) もクリップ頭に置く
- 置き場所: クリップ最初のノートの直前で、そのチャンネルのパケットが無いクロック。元の位置ではすべて同じ値なので**何も起きない** → 互換モードと同一の音になる (render.cpp で波形比較して確認する)。空きクロックが無いクリップは「移動不可」として色を変える
- 古いプラグインは type 4 の未知 param を LFO ディレイとして読むので、このモードの .flp は OPM68 0.7 以上が必須

さらに自由度を上げる案として、**(MDX チャンネル, 音色) ごとに OPM68 を 1 台**にする方法がある。チャンネルラックが「1 音 = 1 チャンネル」になり、クリップを別のチャンネルのトラックに移しても鳴る。代わりに次の互換性を失う。

- 同じ MDX チャンネルで音色が変わったとき、前の音のリリースが切れない (別の OPM68 で鳴るため)
- ハード LFO の位相が台ごとにずれる (曲頭でそろえても、音色の切り替えで台が変わる)
- OPM68 の台数が増える (テスト曲でトラック 14〜27 本)

これは「やむを得ない場合」に当たるので、互換モードの確認後に必要かどうかを決める。

## 未確認事項 (FL Studio での確認が必要)

1. 内蔵の Sampler チャンネルで WAV が読み込まれ、ノートで鳴るか (旧方式は「無効なサンプル」になった)
2. サンプルパス: 絶対パス版は読めるか。相対パス版 (`05_ycmd/TC_GB_arrange_relpath.flp`) は .flp と同じフォルダを基準に解決されるか。ウェブ版は zip で配るので相対パスが使えるかが重要
3. Sampler がノートの長さで音を止めるか (止まらないと PCM8 の「次のノートで切れる」が再現できない)
4. ベロシティと音量の関係 (FL の Sampler が velocity を音量にどう対応させるか)。FM との音量バランス
5. パターン名・トラック名の表示、同じパターンを共有したクリップの表示
6. テンプレートの Pattern 1 に付いていた 226 イベント (3 個) を Pattern 1 にだけ残している。複数パターンで問題が出ないか

## 次のステップ

1. 上の未確認事項を FL で確認し、Sampler チャンネルの作り方を確定する (必要ならテンプレートに Sampler チャンネルを 1 本入れて保存してもらう)
2. ADPCM を MXDRV と聴き比べ (portable_mdx の MXMASK でチャンネル単独描画)
3. ウェブ版: `.flp` + `samples/*.wav` を zip でダウンロード
4. 自由度優先モード: OPM68 0.7 (RESTORE) とスナップショット
